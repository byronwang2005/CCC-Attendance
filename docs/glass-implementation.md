# 玻璃组件实现与验收

## 实现范围

本次按 Apple 的 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 和 [Liquid Glass 演示](https://developer.apple.com/videos/play/wwdc2025/219/)调整 Web 控件。保留现有字体、Logo、水墨三套配色、二维码树景、诗句及业务接口。

| 组件 | 实现 |
| --- | --- |
| 站点抬头 | 保留原有字体、Logo；移除独立光学表面 |
| 正文、指引、编号、行内代码、命令块 | 标准内容表面；取消独立折射及悬浮阴影 |
| 三步导航 | 一层 Regular 风格材质，当前步骤用品牌色编号和浅色选中背景 |
| 身份、时间模式 | 标准轨道与共享折射选中层；受控接口，点击、方向键、Home/End、拖动和取消 |
| 时间模式说明 | 从选项中移到下方，保留原文 |
| URL、日期、时、分 | 统一边界、焦点和触摸高度；点击输入区留白可聚焦；日期时间保留原生 select |
| 下一步、返回、生成更多、复制 | 共用玻璃规范、整块按压形变、浅品牌色主操作、中性次操作 |
| 复制状态 | 复制中、成功、失败及禁用反馈，文字和可访问状态同时更新 |
| 提示弹窗 | Radix Dialog，明确名称、焦点约束、Escape、背景隔离、回焦；标准关闭按钮 |
| 404 | 标准信息区与共享玻璃返回按钮，引用同一份材质 CSS |
| 二维码树景 | 保留原有渲染和操作，周边操作使用共享按钮规范 |

## 渲染与回退

- `GlassEnvironment` 保存辅助设置、质量等级及最多四个活动折射组。
- 水墨最后一次绘制后立即复制帧，避免稍后读取已清空的 WebGL drawing buffer。
- `GlassGroup` 封装 `@samasante/liquid-glass@0.1.1` 的 `draw/lenses` 路径。按实际坐标裁取背景，合成祖先标准表面与轨道底色。光学画布裁剪到控件轮廓，DOM 文字与图标保持清晰。
- 明暗采样平滑调整填充和边缘。分段选中背景直接测量选项边界，缩放时换算回 CSS 坐标。
- 不按 UA 分流。诊断属性分别报告 `canvas`、`backdrop`、`solid`，材质用途与渲染方式分开。
- 120 帧中位间隔持续超过 20ms 时，从最高 DPR 1.5 降至 0.75；低档仍超过 28ms 时改用毛玻璃。质量只降不升，避免反复切换。切换分辨率会重建光学画布，避免库清理时丢失旧上下文影响恢复。
- 初始化错误、上下文丢失有回退；上下文恢复后重建渲染器。不可见组释放渲染器；实体或性能回退时停止组几何帧循环。
- 减少透明度和强制颜色使用实体操作表面。减少动态停用水墨运动、位移弹簧和按压形变。

这是一套遵循 Apple 原则的 Web 实现。系统级背景采样、触觉反馈和原生合成器行为无法由这套 Web 适配层等同实现。

## 依赖调整

- 保留 `@samasante/liquid-glass@0.1.1`。
- 引入 `@radix-ui/react-dialog@1.1.23`。
- 计划中的 `motion@14.0.0` 安装失败：该包引用的 `framer-motion@14.0.0` 在当前 npm 源不存在。改为可安装、支持 React 19 的 `motion@12.23.24`，版本已锁定。两项新增运行时依赖均为 MIT。
- 浏览器测试使用 Playwright、axe-core；QR 测试服务器调用原有本地 API handler，不向生产服务写入数据。

## 可重复验证

```sh
npm test
npm run lint
npm run build
npx playwright install chromium webkit
npm run test:browser
```

浏览器矩阵：Chromium、WebKit × 1280×900、390×844。macOS Chromium 使用 Metal，避免把 SwiftShader 软件绘制成本当作设备图形性能。

自动化覆盖：

- 在真实适配层中对照“折射开启”与“仅折射强度归零”的截图，按钮与选中层各自必须有超过 100 个像素显著变化；其余光学参数保持相同。
- 选中背景与选项边界误差 ≤1 CSS px；连续切换、窗口变化、CSS 缩放、键盘、拖动提交一次和取消恢复。
- 三步流程、身份、复制中/成功、手动时间、错误弹窗、404；保存截图与录屏。
- 弹窗焦点循环、Escape、关闭回焦；WCAG A/AA 自动检查。
- 深色条纹背景下实际画布采样与品牌字色的对比度 ≥4.5:1；
- 减少动态的背景像素稳定、WebGL 不可用、上下文丢失/恢复、减少透明度的实体样式。
- 持续慢帧依次触发高档、低分辨率、毛玻璃；验证低档画布实际像素宽度减小。
- 放大关键文字、短横屏、无水平溢出及操作可达性。

截图、视频和浏览器 HTML 报告属于本地生成物，保持在已有忽略目录中。测试结果与性能摘要见下方验收记录。

## 自动化与性能记录（2026-10-03）

- `npm test`：24 个文件、143 项通过。移除了锁定旧浏览器降级策略和旧 CSS 字符串的断言，增加行为测试；业务、文案、二维码测试保留。
- `npm run lint`：通过。
- `npm run build`：通过。树景 Three.js 分包仍有现有的 >500kB 提示。
- `npm run test:browser`：28 项通过（2 引擎 × 2 视口 × 7 场景）。
- 主流程 axe WCAG A/AA 自动检查：无违规。仍需人工辅助技术验收。

同一台 Apple M1 Pro，改造前提交 `f46b916` 与改造后工作区；每组预热 1.8 秒、采样 4 秒，无并发浏览器测试。该记录度量 rAF 调度，不是实际显示帧的 GPU 测量。

| 引擎 / 视口 | 前 / 后平均 fps | 前 / 后 p95 帧间隔 | 改造后材质 |
| --- | --- | --- | --- |
| Chromium / 1280×900 | 60 / 60 | 16.7 / 16.7ms | 3 组高质量 Canvas |
| Chromium / 390×844 | 60 / 60 | 16.7 / 16.7ms | 3 组高质量 Canvas |
| WebKit / 1280×900 | 60 / 60 | 18 / 19ms | 3 组高质量 Canvas |
| WebKit / 390×844 | 60 / 60 | 19 / 19ms | 3 组高质量 Canvas |

这八次短采样均无 >25ms 帧间隔。软件渲染的 Chromium 也曾触发性能降级；强制慢帧测试确认会先降低实际画布分辨率，再切换毛玻璃，控件仍可操作。

复现性能对照：先启动相同环境下的旧版本服务器，再执行 `node scripts/measure-glass-performance.mjs <旧版本URL> [当前版本URL]`。原始结果保存在 `design-qa/performance.json`。
